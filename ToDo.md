# vega-webgpu roadmap

Tracking the gap to a production-grade, canvas-matching WebGPU renderer. Items are grouped by theme, each noting the observed symptom and the fix.

## Rendering fidelity

- [x] **Rect edge antialiasing is analytic now, which fixes seams generally.** Canvas computes edge coverage analytically (measured: exactly `100 - phase*100` across sub-pixel phases), so two abutting rects produce complementary coverage and it shows only a faint line. Our MSAA coverage was quantized to whole samples, did not complement, and left an obvious white seam (heatmap rows, axis bands). The rect quad is now grown by one device pixel and the fragment shader computes box coverage from the true edges, so MSAA contributes no edge coverage and we reproduce the canvas model. Geometry is untouched, so deliberate sub-pixel gaps survive: the `rect-subpixel` fixture covers eight abutting phases plus gaps of 0.2 to 1.0 px in both axes and matches canvas at 0.000%. heatmap 0.26% to 0.01%. Rejected alternatives: growing rects to overlap, and snapping edges to device pixels, both of which close or widen gaps that are meant to be there.

- [x] **Text blur fixed, rotation and sub-pixel placement.** Each glyph is rasterized into its axis-aligned bounding box (rotation baked in) at its real sub-pixel phase, then drawn as a plain quad on a whole device pixel, so it maps 1:1 to device pixels (crisp, no resampling) _and_ lands exactly where canvas draws it instead of snapped up to half a pixel away. The cache is keyed by dpr, angle and quantized phase (8 steps/px). Rotated radial labels (arc-diagram) ~3.7% to 0.8%. Dense small labels (barley) ~3.2% to 1.0%. Follow-up: SDF/atlas text to close the last text-dense fringe.
- [x] **Rect fill inset fixed.** Rect marks carrying a `strokeWidth` but no `stroke` (common: stroke set on hover only) reserved a transparent stroke band and rendered ~strokeWidth/2 px too small on every edge. Canvas ignores `strokeWidth` when there is no stroke, so we now do too (nested-plot 4.7% to 0.8%).
- [x] **Transparent background matches canvas.** `initialize` forced a white background, so every frame was fully opaque while canvas leaves the background transparent and only fills when one is set (44% of an orthographic map). A missing background now clears to zero alpha. This also exposed that `captureFrame` returned premultiplied alpha while `toDataURL` returns straight, which made anything translucent compare wrong; the readback un-premultiplies.
- [x] **Rules antialias analytically.** 4x MSAA can only express quarter-pixel coverage, so a 1px rule quantized to five levels (51/102/153/204/255) where canvas computes the real fraction. The rule quad grows by one device pixel and the fragment shader computes box coverage from the true edges, the same model as rect. At tenth-pixel offsets the worst channel goes from 31 off canvas to 1. Guarded by the `rule-subpixel` fixture and a max-channel-delta budget, since the differing-pixel count cannot see a change this small.
- [ ] **Thin strokes are still hard on the line/segment path** (diagonal rules, 1px lines, e.g. playfair's price lines). `sline.wgsl` still relies on 4x MSAA. Same fix as rules, but coverage is distance to a butt-capped segment rather than a box: perpendicular distance against half the stroke width, times the along-segment span. `rule-angles` is at 67 worst channel, almost all of it the diagonal fan. Note: naive stroke-centering alone _regresses_ the cross-check (hops 0.54% to 1.13%). The softness, not the position, is the dominant term.
- [x] **Symbol outlines were missing a corner.** extrude-polyline builds no join at the seam when it is told a polyline is closed, so the outer miter at every closed contour's first vertex was simply absent: a stroked square came out with three corners. Rings are reopened at the midpoint of their first segment, which puts every real vertex in the interior and lands the two butt caps on a straight run. symbol-shapes worst channel 153 to 76, and square, cross, diamond and stroke now match canvas ink exactly. This covered all closed stroked paths, so geographic outlines and path marks got it too.
- [x] **Self-intersecting paths fill nonzero, the way canvas does.** A custom star symbol came out hollow in the middle where canvas fills it solid, 182 levels off at the centre pixel. `triangulate-contours` asks tess2 for even-odd and never exposed the option, but it forwards the whole option object, so the winding rule is simply passed through. symbol-custom worst channel 182 to 76, and no spec moved, so map and area holes were already wound for nonzero.
- [x] **Symbol shapes with a closed form are drawn analytically.** `symbolSdf.wgsl` is a template whose `shapeDistance` body is substituted per shape and compiled on first use, so each variant stays branchless. square, diamond and all five triangles are one instanced quad each, with no triangulation and no MSAA-quantized coverage. Worst channel against canvas: square 51 to 12, triangle-up 48/76 to 10/19, triangle 53 to 3, diamond 8 to 1. The `symbol-analytic` fixture holds them at a budget of 25 where the triangulated versions were 76.

  The stroke edge has to grow the shape's own extents rather than offset its distance, since canvas joins with a miter and offsetting a distance rounds every corner. `cross` is excluded for that reason: it is a union of two boxes, and eroding a union is not the union of the erosions, which puts its reflex corners in the wrong place (26 triangulated against 51 as an SDF).
- [ ] **arrow and wedge have no distance function**, so they stay triangulated at 51/76 and 33/74 worst channel, and they are what holds the `symbol-shapes` budget at 80.
- [ ] **The circle edge is off by up to 61 on the diagonal** while matching within 2 horizontally. Routing circles through the SDF template measured neutral (36/57 against 35/61), so the dedicated shader stayed. The remaining error looks like the linear coverage approximation on a curved edge, and wants checking against an exact circle-pixel area.
- [ ] **choropleth**: geographic outlines differ from canvas.
- [x] **map-point-radius stray "flying line".** A contour shaped A to B to A (geographic slivers clipped by the horizon) turns by almost 180 degrees, and `extrude-polyline` puts the miter there either at NaN or thousands of pixels away, smearing one triangle across the canvas. Stroke vertices are now dropped unless they sit within the miter allowance of their own contour. 143 stray pixels to 0.
- [ ] **scatter-plot-contours**: contour lines are drawn very differently from canvas (line construction/curve handling).
- [x] **tree-radial-bundle fixed.** Its curved links are line marks with `interpolate`, which were drawn as straight polylines. Routing them through the shared path tessellation took it from 10.2% to 0.27%.
- [ ] **Line joins**: round joins are used, canvas defaults to miter. Route lines through extrude-polyline (like area/path) for miter parity.

## Missing features

- [x] **Line dashes.** `strokeDash`/`strokeDashOffset` are split into drawn runs on the cpu and emitted as segments, covering straight and curved lines. Group and rect borders dash the same way, since the analytic rect stroke cannot express a pattern. Fixture `line-dashes`, 0.000% against canvas.
- [x] **Symbol geometry is already cached** per (shape, size, strokeWidth) with least-recently-used eviction, and instanced: 0.02 to 0.22 ms a frame in the benchmark. Only gradient-filled symbols bypass it.
- [x] **Symbol shapes**: all shapes (square, cross, diamond, triangle-\*, arrow, wedge, stroke, custom SVG) plus `angle` rotation now render. Circles keep the analytic shader. Other shapes are triangulated once per (shape, size) and instanced. `symbol-shapes` 6.8% to 0.03%, `symbol-angle` 14.3% to 0.001%.
- [x] **Gradient on symbols**: gradient-filled symbols (e.g. a legend swatch) now render via the gradient pipeline (triangulated, per item). The `gradient` spec's radial-gradient circle went 4.6% to 0.007%.
- [x] **Trail marks are implemented**, so all twelve of vega's mark types now render. A trail is one filled ribbon whose width follows each point's `size`, sharing the area shader.

  The shared trail path generator took its width from `item.width || item.height`, where vega's own accessor is `item.size || 1`. That drew every trail as a one pixel line rather than a ribbon, and it was only visible because the fixture was compared against canvas. Covered by the `trail` fixture at 0.016%.
- [x] **Blend modes**, for the four WebGPU can express. vega's `blend` is canvas's `globalCompositeOperation`, and WebGPU blends with fixed function state rather than a programmable one, so multiply, screen, darken and lighten fall out of its factors and operations. All four reproduce canvas exactly, worst channel 1, in the `blend` fixture.

  A pipeline is built per blend mode and cached, and a run of rects starts a new draw when the mode changes. The rect shader discards fragments with no coverage: the quad is grown a pixel past the rect, and under a min or max blend those empty fragments would still darken the destination, which is what put a fringe around a `darken` rect.
- [ ] **The other blend modes need the destination inside the shader**, which WebGPU cannot provide without a copy: overlay, difference, color-dodge, color-burn, hard-light, soft-light, exclusion, hue, saturation, color and luminosity. They warn once and draw normally. The `blend-unsupported` fixture pins that. Doing them properly means rendering blended marks to their own target and compositing, which is worth it only if specs actually use them.
- [x] **Every mark honours blend**, not just rect. rect, rule and area reproduce canvas exactly (worst channel 1); symbol, arc, path and line blend correctly but keep an edge error, covered by the `blend-marks` fixture.

  Every shader now discards a fragment with no coverage. Marks grow their geometry past the shape so an analytic edge is not clipped, and those empty fragments would otherwise still reach the blend state: under a multiply they brighten the destination and under a min they darken it. That alone took rule from 65 to 1.
- [ ] **An antialiased edge under a blend is still off** on marks that carry their coverage in alpha (symbol 88, path 71, arc 53, line 141 worst channel). One set of blend factors cannot both multiply by the destination and weight the source by its own alpha. The fix is a shader variant per mode that pre-weights the colour, the same substitution the symbol distance functions use, so `multiply` would emit `mix(vec3(1), rgb, a)` and pair with a `dst`/`zero` factor.

## Performance

- [x] **Geometry is cached per item instead of rebuilt every frame.** `cacheShapes` existed but defaulted off and only covered `shape` marks. It is on by default now, bounded to 4096 entries with least-recently-used eviction, and the same helper backs `path` as well. A colour-only change rewrites colours over the cached positions instead of triangulating again. choropleth re-render 67.2 ms to 12.8 ms, which is faster than canvas at 47 ms.
- [x] **Measured on real hardware, and the software rasterizer was most of it.** `WEBGPU_HARDWARE=1` runs the benchmark on the machine's own adapter and drops the forced Vulkan flags, so the browser picks its own backend. Frame cost against SwiftShader: contour-map 40.5 ms to 4.8, choropleth 13.3 to 7.0, airports 8.9 to 4.1, tree-radial-bundle 41.9 to 26.7. choropleth beats canvas by 6.8x (7.0 against 47). Nothing here argues for moving tessellation into a compute shader: on hardware the GPU side is already small, and under SwiftShader it would be adding to the part that is slow.
- [x] **basis and bundle curves are evaluated on the GPU.** tree-radial-bundle is 764 faceted line marks, so every frame built 764 SVG path strings, parsed them, flattened them, extruded a stroke mesh and issued 764 draws. `curve.wgsl` takes the control points as instances and evaluates the uniform cubic B-spline in the vertex shader, one instance per span, with the joints offset along the analytic tangent so neighbouring quads share an edge exactly. Overlapping them would double-blend, and this spec draws at strokeOpacity 0.2.

  On hardware: line 9.4 ms to 1.1, group 21.8 to 4.8, the spec 27.0 ms to 11.7. The batch only merges draws whose bind groups are the same object, so holding one is what took it from 22.6 to 11.7; rebuilding it per curve silently defeated the merge.
- [x] **Attributed the rest of a frame.** `_draw`, `_submit` and `_reinit` are reported alongside the per-mark timings. tree-radial-bundle spends 3.4 ms in mark drawing and 0.15 ms encoding, so the balance is GPU. It is not vertex bound: 4, 8 and 16 sub-segments per span all cost the same, only fidelity changes. Every spec also carries a ~4 ms floor, which is the benchmark awaiting `onSubmittedWorkDone` and draining the GPU each frame, something real rendering does not do. Treat the totals as upper bounds.
- [x] **Measured what a first frame costs, and prebuilding does not fix it.** First frame against steady state on hardware: tree-radial-bundle 196 ms against 16, choropleth 75 against 7, scatter-plot 40 against 6. That is pipeline setup, and it is worth knowing it is there.

  Creating the pipelines is not the cost. Building every mark's pipelines takes 0.2 ms for all eleven, because the browser defers the real compilation until a pipeline is first used in a draw. Pre-creating them therefore cannot remove it: warming every mark made the first frame 40 to 56 ms *worse* (symbol-shapes 7.7 to 64.3, scatter-plot 47.8 to 88.4), since it compiles pipelines the spec never draws, and warming only the marks the scene contains measured neutral (scatter-plot 52.3 either way). The warm API was removed rather than shipped as a no-op.

  `createRenderPipelineAsync` is the untried candidate: it is specified to resolve only once a pipeline is usable without further delay, so it should move the compile off the first frame. It needs the render path to await pipelines, which is why it was not tried here.
- [x] **Pipelines are cached by descriptor** in `ctx._pipelineCache`, keyed by shader, entry point, sample count and vertex layout, so marks that share a shader and layout share one pipeline and a `_markCache` reset no longer rebuilds them.
- [ ] **Shader variants are already a dictionary lookup.** Pipelines live in `ctx._shaderCache` and `res.sdfPipelines`, compiled on first use and fetched by key after, so per-mark specialisation would not move the numbers: CPU mark drawing is 3.4 ms of a 13 ms frame and shader setup is none of it. Worth revisiting only if a profile shows pipeline switching itself costing.
- [ ] **Curves other than basis and bundle still tessellate on the CPU.** cardinal, catmull-rom and monotone are all cubic splines with a different basis matrix, so `curve.wgsl` extends to them by substituting the matrix, the same way the symbol shaders substitute a distance function.
- [x] **Uniform buffers are reused across draws.** Every `draw` call minted a uniform buffer and a bind group, and a spec with hundreds of small line marks paid for hundreds of both per frame. They are keyed by resolution and offset now. Note that outright sharing one buffer is wrong: the render queue defers every draw to the end of the frame, so one buffer rewritten per group hands every draw the last group's offset, which is what `line-curves` and `regression` caught.
- [ ] **Per-draw bind groups remain.** The buffers are shared but each draw still builds its own bind group. Cache those against the same key.
- [ ] **movies-sort**: ~3.4 s draw (giant 95k-px-tall canvas).

## Robustness / bugs

- [x] **Hostile input has a suite.** `test/render/scenes-hostile` feeds the renderer what a mark should never see: NaN and Infinity coordinates, zero and negative extents, values a billion pixels outside the viewport, absent styling, and shapes with too few points. Nothing is compared against canvas, since canvas has its own opinions about nonsense. What is asserted is that the device survives, the renderer keeps it, and the frame is not smeared: one NaN vertex stretches its triangle across everything, which is the failure the geographic miter bug produced. All five cases pass, drawing 0.4% and 0.8% of the frame where they draw at all.

  Two of the five failures it found first were the fixtures, not the renderer: JSON has no literal for NaN or Infinity, so those travel as sentinels the harness revives, and vega's own path parser throws on a malformed path string before any renderer sees it.
- [x] **Blank renders wherever there is no compositor.** `getCurrentTexture()` destroys the GPU device on a headless runner, roughly 15 ms after it is handed out, and every later `requestAdapter()` returns null. `configure()` and an offscreen pass both survive, and no launch flag combination changes it (seven were tested). `wgOptions.offscreen` renders into a texture the renderer owns and never touches the swapchain. Bisected by test/render/webgpu-smoke-diagnose.spec.ts.
- [x] **A destroyed device left the renderer dead.** A loss with reason `destroyed` returned early without clearing `_device`, so the renderer kept using it and every later capture rejected in `mapAsync`. Every loss reason now drops the device and its pipelines, capped at three automatic recoveries, and a failed capture retries once on a fresh device.
- [x] **Buffer uploads exhausted a constrained runner.** `mappedAtCreation` allocates a JS ArrayBuffer per buffer and a frame makes one per mark, so even a 32-byte uniform buffer failed to create. Uploads go through `queue.writeBuffer`, which reuses the staging ring.
- [ ] **Oversized canvas crash** (movies-sort): a 95356-px-tall canvas exceeds WebGPU's `maxTextureDimension2D` (8192) so the MSAA/depth/swapchain textures fail to create and the frame errors out. Short-term: detect the limit, warn once, and skip the frame instead of crashing (implemented). Long-term: tiled rendering for canvases larger than the texture limit.
- [ ] `powerPreference` warning on Windows (cosmetic, crbug.com/369219127).

### Known issues (from code review)

Findings from a full review of the working tree. Fixed items are kept for the record, open ones are ordered by severity.

- [x] **`renderLock` resolved `renderAsync` too early.** A render arriving mid-frame was coalesced into `_pendingRender`, but `_renderPromise` still pointed at the already-settled in-flight frame, so `renderAsync` (and the test harness) resolved before the newest scene was drawn, screenshotting a stale canvas. Deferred renders now expose a stand-in promise that settles only once the flushed frame does.
- [x] **A failed frame wedged the renderer.** `_render`'s `catch` cleared `_isRendering` but never flushed `_pendingRender`, so a queued render was silently dropped and its awaiter hung forever. All frame exits (completion, early return, failure) now drain through one `_finishFrame` path.
- [x] **The oversized-canvas early return stranded pending work** for the same reason. It now drains through `_finishFrame` too.
- [x] **Dead dirty-bounds tracking.** The `dirty()` override walked the group chain and unioned bounds into `_dirty`/`_tempb` on every item, but nothing ever read them, every frame redraws the whole scene. Removed, reinstate with partial redraw.
- [x] **Swapchain reconfigure.** `ctx.configure()` now runs once per device in `_reinit`, not per frame.
- [ ] **Per-item buffer churn in `text`/`rect` gradient paths**: a uniform buffer, bind group and vertex buffer are allocated per item per frame and never explicitly released, leaning entirely on GC. Pool or batch them (ties into the retained-geometry work under Performance).
- [ ] **`markClip` allocates a scissor rect per mark per frame**. Hoist to the mark's cached resources.

## Tests (current focus)

- [x] **A fidelity report ranks every case by how far it is from canvas.** `WEBGPU_FIDELITY=1 npx playwright test fidelity` renders all 118 specs and fixtures and ranks them by max and mean channel error, not just the share of pixels that moved. The two say different things: a soft antialiasing difference is a high pixel count with a low max, a misplaced or miscoloured mark is the reverse. This is what surfaced the image premultiplication bug, which the pixel count reported as 0.000%. 21 of 118 cases match canvas to within 2 levels everywhere.
- [ ] **Six specs are still 255 off somewhere**: choropleth, driving, font-size-steps, map-fit, panzoom, scales-discretize. panzoom was traced to axis labels placed one pixel low, 42 pixels in all; the phase quantization is not the cause, since rounding the phase up to 1.0 and wrapping it to 0.0 land the anchor identically. The others are unexamined.
- [ ] **Highest mean channel error**, meaning a systematic rather than local difference: regression 21.0, panzoom 14.1, splom-outer 14.0, line-curves 13.1. These are the cases where every inked pixel is somewhat wrong rather than a few being very wrong.
- [x] **Antialiased pixels are counted.** Pixelmatch classifies an isolated high-contrast pixel as antialiasing, which is exactly what a one pixel marker shift looks like, and left it out of the count. That hid 22939 differing pixels against 21231 counted, and reported `airports` as 0.000% with 13 marks visibly out of place. `includeAA: true`, budgets remeasured against the whole difference.
- [ ] **Canvas presentation is untested.** The harness renders offscreen everywhere so local and CI take the same path, which means `getCurrentTexture()` and the swapchain present are exercised by nothing. It is one call, and it cannot run on a compositor-less runner, but a regression there would ship silently. Wants a browser check somewhere that a real canvas actually shows the frame.
- [x] **Test integrity: a blank render fails the gate.** Two blank images diff at 0%, which is how CI looked healthy while every spec rendered blank. The smoke test now captures a frame and fails unless at least 5% of it has any alpha, and reports the device state when it does not. Still wanted for the full suite: a non-arbitrary per-spec check, for example asserting the output is not a single uniform colour.
- [x] **All specs are tested.** The corpus is derived from `test/specs-valid` (all 117 specs) minus 9 documented exclusions (remote data, force layouts, wordcloud, stress demos, oversized movies-sort). New specs are picked up automatically. Gap-revealing specs (tree-radial-bundle ~12%, symbol-shapes ~7%) are tested with documented budgets that fail on regression.
- [x] **Feature canaries.** `line-curves` (basis/monotone plus a `defined` gap) stays a spec; the dash, sub-pixel rect, corner, rule-angle, symbol-shape and text-layout canaries are scenegraph fixtures under test/render/scenes, driven straight into the renderer the way vega tests vega-scenegraph.
- [ ] **Parameter coverage**: exercise multiple settings per feature (curve types, symbol shapes, line dashes, autosize modes) so regressions in a single parameter are caught.
- [x] **Inspectable output**: HTML report with each spec's webgpu/canvas/diff attached (always, passing specs included). `RENDER_ARTIFACTS=1` also writes the raw per-spec PNGs to `test/render/output/`. CI uploads both the report (`render-report`) and the raw images (`render-images`) as downloadable artifacts.
- [ ] **Run the full check suite on GitHub**: typecheck, lint, build and the render tests all run in GitHub Actions on every push/PR ([ci.yml](.github/workflows/ci.yml)), uploading the report + raw images as artifacts (done). Still to do: publish the HTML render report to GitHub Pages so the webgpu-vs-canvas gallery is browsable online next to the live demo, not only as a download, and gate merges on the checks passing.
